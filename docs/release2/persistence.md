# Persistence

In our application we use SQLite as our database solution for persistent storage of data, accessed by Hibernate ORM.
SQLite stores the data, such as users and posts, in a single local file. Hibernate automatically maps our Java objects to database tables and handles saving and loading, so that changes in the application are instantly stored in the database file.
The database schema (tables, columns, types) is automatically generated by Hibernate based on the entity classes in the project (e.g. `core.User` and `core.Post`).
Each entity class corresponds to a table in the SQLite database, and the class fields define the table columns.

The document metaphor is common in desktop applications such as text editors or graphical editors, where users explicitly open, edit, and save files. In this model, users are responsible for managing these actions themselves.
Implicit saving means that all user actions are automatically persisted as they happen.
This approach is standard for modern web and mobile apps, especially social platforms. In such models, there are no explicit save buttons – users can trust that their data is always up-to-date and safely stored.

A social media application like twitter-clone is not organized around user-managed documents.
Users expect their actions (posting, editing their profile, etc.) to be saved automatically, without any manual steps.
The document metaphor would add unnecessary complexity for the user and increase the risk of data loss if users forgot to save.
Therefore, we use implicit saving for twitter-clone as it is the natural and user-friendly choice.
It matches how real-world social media works and provides a streamlined experience for users.
