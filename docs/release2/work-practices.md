# Work practices

We in Group 8 have discussed and chosen guidelines for our work practices.
We have scheduled fixed weekly meetings to work physically on the project and discuss progress together.
Other meetings or gatherings are arranged within the group via private communication channels.

During the physical meetings, we create GitHub Issues that are then assigned to team members.
This makes each member’s responsibilities clear, and we strive to distribute tasks fairly.
At these meetings, we also discuss our goals and create new issues as needed.
We perform pair programming several times when we believe it will be effective.

Early on, we established concrete guidelines for code management and project organization, including:

- Using meaningful commit messages, following Conventional Commits
- Using clear pull request titles, following Conventional Commits
- Applying GitHub labels consistently
- Using GitHub Projects to track tasks
- Performing code reviews
- Avoiding pushing commits directly to master/main unless necessary

We also aim to minimize prolonged discussions when disagreements occur. Instead, we try to reach a compromise quickly, allowing us to test ideas in practice and determine what works best.
